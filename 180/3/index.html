The power of flow models · flow matching from scratch

Overview

Flow models learn a velocity field that carries pure noise to the distribution of real images. In this project we experiment with denoising and generating images, first with a pretrained model (PixNerd) and then with a UNet that I trained from scratch on MNIST.

Part A · The power of flow models

The sampling functions

interpolate · one_step_denoise · euler_sample · cfg_velocity · edit · visual_anagrams · make_hybrids 
def interpolate(image, noise, t):
  return (1-t)* noise + t*image

def one_step_denoise(x, t, condition, predict_velocity):
  v = predict_velocity(x, t, condition)
  return x + (1-t)*v

@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    states = []
    x = x_start
    t = t_start
    states.append((t,x))
    k = 0
    while t < 1:
        k += 1
        h = min(step_size, 1 - t)
        x = x + h * velocity(x, t)
        t += h
        if k%5 == 0 or t == 1:
          states.append((t,x))
    return x, states

def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    v = predict_velocity(x, t, condition)
    null_v = predict_velocity(x, t, null_condition)
    return v + w * (v - null_v)

def edit(image, noise, t_start, condition, predict_velocity, w=7, step_size=0.02):
    noisy = interpolate(image, noise, t_start)
    x, states = euler_sample(noisy, t_start, step_size, lambda x, t: cfg_velocity(x, t, condition, w, predict_velocity, null_condition))
    return x

def rotate180(x):
    return torch.flip(x, (-2, -1))

def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):

    x, states = euler_sample(noise, 0, step_size, lambda x, t: (cfg_velocity(x, t, condition_a, w, predict_velocity) + rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity))) / 2)
    return x

def lowpass(x, sigma=16.0):
    kernel = 2 * round(16.5 * x.shape[-1] / 64) + 1
    return gaussian_blur(x, [kernel, kernel], [sigma, sigma])

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def velocity(x, t):
        v_a = cfg_velocity(x, t, condition_a, w, predict_velocity)
        v_b = cfg_velocity(x, t, condition_b, w, predict_velocity)
        return lowpass(v_a) + v_b - lowpass(v_b)

    x, states = euler_sample(noise, 0, step_size, velocity)
    return x

1.1 · Constructing noisy training inputs

Blending an image with Gaussian noise. t can be thought of as the fraction of the blend that comes from the image; the remaining 1 − t is noise.

1.2 · Classical denoising

At each t we divide the noisy image by t to restore the image's brightness, then use a Gaussian blur to try to erase the noise.

Choosing the blur strength

For each t, I tried σ = 1, 2, 4, 8 and 16 and kept the one whose blurred result had the lowest mean squared error against the original image.

1.3 · One-step denoising

Using one-step denoising, the picture is somewhat recovered. However, the smaller details are lost, since the model is estimating the average of all the original images that could have produced the noisy input. The noisier the input, the blurrier the result.

1.4 · Visualizing velocity

These visuals show the predicted change to the noisy image, (1 − t)vθ, vs. the ground-truth change x1 − xt, the difference between the original and the noisy image. The error image is the RMS, over the RGB channels, of the difference between the predicted and ground-truth updates.

Where the error lands

The errors in all three examples are in the high frequencies, and they are most prominent in the noisiest image (t = 0.25). This makes sense, since one-step denoising cannot recover fine details.

1.5 · Iterative denoising with Euler sampling

Denoising iteratively lets the model fill in details that are plausible for the picture. The image looks sharper and more realistic, but because noising the image is lossy, the final image is not a perfect reconstruction; this can be seen in the person disappearing from the final image.

1.6 · Generating images from noise

These images are generated from pure noise, conditioned on "a high quality photo". The random starting point is why the pictures are different. However, these pictures are malformed and very unrealistic. This is because, without guidance, such a generic prompt only weakly steers the sampling, so the samples spread over a broad range of images, including many implausible ones. This generic prompt favors generating people.

2.1 · Classifier-free guidance

To combat the issues from above, we guide the image generation by pushing it further in the direction of the condition. The model predicts one velocity with the prompt and one with an empty prompt, and the guided velocity is vc + w(vc − vu). I used w = 7, which pushes the velocity past the prompted prediction by 7 times the difference between the two.

With and without guidance

Using guidance allows for more realistic pictures, instead of the malformed and sometimes scary ones above. The downside of guidance is the loss of variety: the higher w is, the more the generated pictures look like each other. This can be seen in the CFG outputs, which are all front-facing portraits of people.

3.1 · Image-to-image editing

The noisy images here are reconstructed into realistic-looking images, but they often diverge from the original at high noise levels (small starting times), since not enough of the image is kept. My favorite is the guy holding up a mirror to his face, when the original image is a rocky coastline.

Editing hand-drawn and web images

My hand-drawn images used very thin pencil strokes, so the noisier ones were reconstructed into blank white canvases or gibberish paperwork.

3.2 · Text-guided image editing

The noisier the starting image, the more liberties the model can take to guide it in the direction of the prompt; the less noise, the more the result resembles the original image. As the starting time approaches 1, the model can no longer change the bigger details and only changes the smaller ones.

Campanile → a talking redwood tree

Rocks → two mythical creatures

Pool room → two architects

3.3 · Visual anagrams

The visual anagrams work by conditioning on two different prompts. At each Euler step, one prompt's velocity is computed on the upright image, while the other's is computed on the image turned upside down and then flipped back, and the two are averaged. This creates the illusion of a different picture when the image is turned upside down.

Earth from the ISS / big wave surfer

Skier / snow fox

3.4 · Hybrid images

The hybrid images work by computing the velocity for two different prompts and, at each Euler step, combining the low frequencies of one with the high frequencies of the other. This allows the image to look like one thing from up close and another from far away.

class Conv(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(in_channels, out_channels, 3, 1, 1),
            nn.BatchNorm2d(out_channels),
            nn.GELU()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.conv(x)
        return x

class DownConv(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(in_channels, out_channels, 3, 2, 1),
            nn.BatchNorm2d(out_channels),
            nn.GELU()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.conv(x)
        return x

class UpConv(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.conv = nn.Sequential(
            nn.ConvTranspose2d(in_channels, out_channels, 4, 2, 1),
            nn.BatchNorm2d(out_channels),
            nn.GELU()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.conv(x)
        return x

class Flatten(nn.Module):
    def __init__(self):
        super().__init__()
        self.flatten = nn.Sequential(
            nn.AvgPool2d(7),
            nn.GELU()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.flatten(x)
        return x

class Unflatten(nn.Module):
    def __init__(self, in_channels: int):
        super().__init__()
        self.unflatten = nn.Sequential(
            nn.ConvTranspose2d(in_channels, in_channels, 7, 7, 0),
            nn.BatchNorm2d(in_channels),
            nn.GELU()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.unflatten(x)
        return x

class ConvBlock(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.block = nn.Sequential(
            Conv(in_channels, out_channels),
            Conv(out_channels, out_channels)
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.block(x)
        return x

class DownBlock(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.block = nn.Sequential(
            DownConv(in_channels, out_channels),
            ConvBlock(out_channels, out_channels)
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.block(x)
        return x

class UpBlock(nn.Module):
    def __init__(self, in_channels: int, out_channels: int):
        super().__init__()
        self.block = nn.Sequential(
            UpConv(in_channels, out_channels),
            ConvBlock(out_channels, out_channels)
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.block(x)
        return x
UnconditionalUNet 
class UnconditionalUNet(nn.Module):
    def __init__(
        self,
        in_channels: int,
        num_hiddens: int,
    ):
        super().__init__()
        D = num_hiddens
        self.conv_in = ConvBlock(in_channels, D)
        self.down1 = DownBlock(D, D)
        self.down2 = DownBlock(D, 2 * D)
        self.flatten = Flatten()
        self.unflatten = Unflatten(2 * D)
        self.up1 = UpBlock(4 * D, D)
        self.up2 = UpBlock(2 * D, D)
        self.conv_out = ConvBlock(2 * D, D)
        self.out = nn.Conv2d(D, in_channels, 3, 1, 1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        assert x.shape[-2:] == (28, 28), "Expect input shape to be (28, 28)."
        e1 = self.conv_in(x)
        e2 = self.down1(e1)
        e3 = self.down2(e2)
        u = self.unflatten(self.flatten(e3))
        u = self.up1(torch.cat([e3, u], dim=1))
        u = self.up2(torch.cat([e2, u], dim=1))
        u = self.conv_out(torch.cat([e1, u], dim=1))
        x = self.out(u)
        return x

1.2 · Using the UNet to train a denoiser

Adding Gaussian noise to MNIST test digits using different standard deviations σ.

1.2.1 · Training

The UNet is able to denoise pretty well after the first epoch and recovers the digits almost completely after the 5th epoch.

1.2.2 · Out-of-distribution testing

The UNet stops working on images with much more noise than the σ = 0.5 it was trained on (σ = 0.8 and 1.0), because they have less information than what the model needs to accurately rebuild the digit, and it never saw noise that strong in training.

1.2.3 · Denoising pure noise

Trying to denoise pure noise results in the output being the average of all the training digits.

What the outputs show

Pure noise carries no information about which digit it should become, so the output with the lowest MSE loss is the average of all the training digits.

2.3 · Sampling from the UNet

The time-conditioned UNet still has a hard time generating realistic digits because the model has no class information. It has to decide which digit to generate from the starting noise alone, which can result in hybrid digits if it starts between two digits. Unlike the one-step UNet from 1.2.3, its outputs have defined strokes, because it takes many small steps that refine the details.

2.4 · Adding class conditioning to the UNet

By adding class conditioning, the model is able to pull the generations in a more realistic direction, while the guidance (γ = 5) reduces the variation within each digit.
